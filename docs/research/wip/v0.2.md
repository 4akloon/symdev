## G1 (branch `gaps`, worktree `~/worktrees/symdev/gaps`)

Items in this branch's order: (1) scaffold's absolute SDK paths, (2) `RUSTFLAGS` vs the
libcalls build, (3) a stalled body, (4) `RustSdkPackage::REQUIRED` and the SDK's examples.
Index signing (gap 2 above) is the other agent's (`index-signing`); its files are not touched.

Findings (experiments 110, 111 in `docs/research/experiment-backlog.md`):
- (1) Link `build/rust-sdk` → the directory **above** `symbian-rs` (package root or checkout
  root), project paths `build/rust-sdk/symbian-rs/...`. A link to `symbian-rs` itself fails:
  cargo joins `../../../crates/symdev-locale` lexically. Relative `build.target` in a config
  file = relative to the dir holding `.cargo/` (any cwd); on the CLI = cwd. Re-pointing the
  link at an older-mtime tree leaves cargo `Fresh` (stale) → symdev wipes `build/cargo` when
  the link target changes.
- (2) `cargo rustc ... -- -Zdefault-visibility=hidden` keeps user RUSTFLAGS /
  CARGO_ENCODED_RUSTFLAGS / config rustflags and adds ours to the linked crate only;
  objects identical to today's. CARGO_ENCODED merge drops config flags; profile-rustflags
  hits host build scripts and changes metadata.

Decisions: `RustSdkLink` (symdev-build) owns the link and the wipe; scaffold writes
link-relative paths and the resolved SDK's `rust-toolchain.toml`; `symdev build` refuses
absolute paths into another SDK (lists file:line, old and new line) and a
`rust-toolchain.toml` channel different from the SDK's (no file → no check).
